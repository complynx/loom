# Full application runtime QA, 2026-10-11

The complete Linux application passed the bounded functional checks below with real PostgreSQL, River admission/worker scheduling, Docker metadata discovery through the restricted Docker proxy, the actual sandbox supervisor/worker Unix-socket path, production module bridge/coordinator, and artifact storage. Authentication introspection and Responses/token-count endpoints were deterministic HTTPS test peers. No real model or production issuer was used.

The API was built from the working-tree source before the diagnostics/UI changes made later in this QA session. - The dynamic result imported the acceptance blob into durable artifact storage. Its SHA-256 is `219a43644db4c08317976f85ba5aa7b7a1d04f2a55a536dd337e29776b90af96`, length 51 bytes, MIME `text/plain`. A public HTTP temporary handle was created and downloaded. The downloaded text exactly matched the original fixture bytes. [artifact-handle.json](artifact-handle.json), [download.txt](download.txt). Handle expiry and alternate-owner denial were not exercised in this lane.
- A module write stopped at `waiting_approval`. Explicit HTTP approval and duplicate submission with the same idempotency key succeeded. The fixture committed once and deliberately dropped its reply. The run became `reconciling`; the acceptance container was restarted with its volume retained. Explicit HTTP resume completed the same run through status recovery. PostgreSQL contains one succeeded write operation and the retained fixture state contains one applied operation. No independent HTTP RPC counter was installed; this proves durable state and recovery, not an exact transport-attempt count. [write-waiting-approval.json](write-waiting-approval.json), [write-after-lost-reply.json](write-after-lost-reply.json), [write-completed.json](write-completed.json), [acceptance-state.json](acceptance-state.json), [durable-db.txt](durable-db.txt).

- HTTP steering submitted during an intentionally delayed inference reached the next provider request as `QA_STEERING_APPLIED`; the run completed. [steering-completed.json](steering-completed.json), [provider-11.json](provider-11.json).

## Shutdown boundary under PostgreSQL outage

The API exited 0 without OOM or SIGKILL, but the strict external five-second bound was not met: Docker's SIGTERM-to-exit events measured **5854.65 ms**. The runtime logged `duration_ms:5000`, `deadline_exceeded:true`, `shutdown component deadline exceeded`, and `shutdown checkpoint deadline exceeded`. Docker CLI wall time was 6157 ms. This is a boundary finding, not a clean shutdown PASS: internal waiting is bounded, while the complete external exit and checkpoint completion under database loss are not proven within five seconds. [signal-to-exit.json](signal-to-exit.json), [shutdown-api-pg-outage.json](shutdown-api-pg-outage.json), [api.log](api.log).

## Reproduction and limits

[compose.yaml.txt](compose.yaml.txt), [config.yaml.txt](config.yaml.txt), [peers.go.txt](peers.go.txt), and [driver.ps1.txt](driver.ps1.txt) preserve the fixture and driver. Copy them into `management.local/full-runtime-qa`, run the peer's `init` mode from the repository root, compile its Linux binary, build the indicated application image, and start the standalone Compose file. The replay source includes the corrected fixture key length, request field extraction and text-only answer. Raw [driver-results.txt](driver-results.txt) also records initial disposable-driver mistakes; none required product edits.

The project used API port 58180, acceptance port 58190, unexposed PostgreSQL, and explicit subnet `10.254.248.0/24`. Docker's default address pools were exhausted, so read-only network inventory was used to choose this available subnet. No existing network or service was modified. Confinement is preserved in [containers.jsonl](containers.jsonl).

No disk-full/ENOSPC, real inference quality/capability, installed Zitadel, production deployment, backup restore, load capacity, or complete browser/UI acceptance was exercised. The acceptance fixture uses fixed disposable bearer tokens. The test issuer validates those tokens by introspection but does not reproduce full Zitadel behavior or JWT signing. TLS peers and all test state contain no production credentials.

All seven owned containers, four volumes and the owned network were removed; filtered Docker listings were empty. Disposable TLS private key, CA and auth-key files were removed from scratch. The local tagged build image remains as a replay artifact. [cleanup.txt](cleanup.txt).

# Observability for complynx.net

Identity-cache counters, claim-age histogram, purge event and operational limits are described in the [cache contract](identity-cache.md).

Repository rename: use the coordinated [Loom receiver/Alloy patch](validation/2026-10-12-loom-rename-server.patch). Historical QA patches preserve their original names. Deploy the updated receiver before enabling `updated-loom` dispatch.

The server uses Grafana Alloy with Grafana Cloud Prometheus remote_write and Loki
Docker log ingestion. The application adds no push credentials or telemetry SDK.
A fixed Prometheus 0.0.4 exporter uses standard Go; there is no general registry,
untrusted metric registration or new Go dependency.

## Application configuration

```yaml
observability:
  metrics_listen: ":9090"
  log_level: info
  log_payloads: false
```

Levels are `debug`, `info`, `warn`, `error` (case insensitive). DEBUG includes
operation completion and authenticated user/actor/org identifiers. INFO includes
HTTP completion, run admission/checkpoint and dependency recovery. WARN reports
uncertain effects, deadlines and unsuccessful tool operations. ERROR reports
broken dependencies, model/worker failures and HTTP 5xx. Normal cancellation and
access denial are DEBUG; successful health polling is also DEBUG.

For explicit troubleshooting, set `log_level: debug` and `log_payloads: true`.
Payload logging fails configuration validation at other levels. It records bounded
4 KiB diagnostic request/model payloads; JWT signatures become `***`, while header
and claims remain visible. Opaque tokens, passwords, API keys, encrypted reasoning,
base64 and image URLs are masked. Nested JSON argument strings are also redacted.
The credentials themselves never appear in INFO/WARN/ERROR logs. DEBUG contains
personal content and claims: keep it disabled during normal operation and respect
Docker/Loki retention. Redaction cannot recognize an arbitrary opaque secret
written into free text; do not use debug payload mode for unrestricted secrets.

## Server wiring

1. Create the dedicated external network `clx-observability` on the deployment
   host before using the Compose overlays. This is an operator deployment step.
2. Merge [harness overlay](../deploy/observability/harness.compose.yaml) with the
   harness profile, preserving any existing application networks. Only Alloy and
   the API need this metrics network. No host port or Traefik route exposes 9090.
   Port 8080 serves the authenticated API; `/metrics` is absent there.
3. Local `server_configs/configs/alloy/config.alloy` now has the scrape target
   `loom:9090`, job `integrations/loom`, instance `complynx.net`.
   The existing remote_write credentials/receiver are reused. Deprecated `env`
   calls were updated to Alloy `sys.env`; the target and original pipeline were
   validated together. Alloy Compose joins the dedicated external network.
4. Existing Docker log ingestion already collects JSON stdout. Do not add a
   second log source. Query JSON fields at read time instead of indexing run,
   operation, request or user IDs as Loki labels.
5. Import [alert rules](../deploy/observability/alerts.yaml) into the existing
   Grafana Cloud Prometheus ruler or Grafana-managed alerts. Enable only once the
   scrape target is deployed. No alerts or notification routes were published.

No production deployment or restart was performed. The local server configuration
patch is included with [validation evidence](validation/2026-10-11-observability/README.md).

## Metrics and diagnostics

HTTP counters/histograms use registered route patterns, bounded method/status
labels and include SSE lifetime. `X-Request-ID` is generated by the application;
client-provided IDs cannot inject log content. Run admission links request ID to
run ID; execution and write checkpoints supply run/operation IDs in logs only.

Database snapshots refresh every 15 seconds, with a two-second query budget.
Scrapes read memory only. Failed collection retains the last successful snapshot,
marks database availability down and preserves its timestamp for the stale alert.
Durable gauges survive application restarts: runs by state, River jobs by state,
unknown inference/summary steps, unresolved writes, credits reserved, oldest
reservation/queued run age, and artifact/tombstone bytes. Filesystem gauges report
space available to the runtime UID. These are aggregate diagnostics, not financial
settlement APIs. No user/model/module/run IDs become metric labels.

Dependency gauges cover PostgreSQL collection, current discovery trust, artifact
volume and sandbox supervisor IPC. The sandbox ping starts no child worker. A valid capacity response also proves
supervisor IPC availability, so full worker utilization does not falsely mark it
down. It does not prove arbitrary JS succeeds.
Application health/readiness retain their separate contracts. Execution operation
histograms distinguish success/error/cancelled/timeout/unknown/denied when known.

Supervisor logs `sandbox.worker_killed` without script/error contents. Container
OOM and resource use remain Docker/cAdvisor responsibilities; a lost supervisor
is visible through the sandbox dependency alert. Shutdown elapsed time and deadline
outcome are persisted in the final JSON log, since the metrics process then exits.

Example Loki queries:

```logql
{job="integrations/docker",instance="complynx.net"} | json | service="loom" | level="ERROR"
{job="integrations/docker",instance="complynx.net"} | json | run_id="<run UUID>"
{job="integrations/docker",instance="complynx.net"} | json | event="sandbox.worker_killed"
```

[Prometheus text format](https://prometheus.io/docs/instrumenting/exposition_formats/)
and [Alloy structured logs](https://grafana.com/docs/alloy/latest/monitor/monitor-structured-logs/)
define the integration format. Cloud delivery and notifications still require
post-deployment acceptance; local validation is not delivery proof.

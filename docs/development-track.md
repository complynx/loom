# Дальнейшая разработка

Этот трек отделяет реализованные возможности, оставшуюся приёмку и новые функции. Установка и сопровождение описаны в [startup](startup.md) и [operations](operations.md). Правила проверки: [QA](qa.md); текущие границы: [limitations](mvp-limitations.md).

Старые ID сохранены для ссылок. Отметка выполнения относится только к указанной области. Статус конкретного сервера не является частью этого трека.

## Завершённая основа

- [x] **A03/A04 · Поставка и startup.** Main публикует образы. Startup выполняет миграции и сохраняет ключи; панель поддерживает proxy SSO или direct PKCE. Приёмка конкретной установки выполняется отдельно.
- [x] **B01 · Реальный модуль, ограниченная локальная интеграция внешнего сервиса.** Native discovery, вызовы через JS broker и фильтрация административных методов по правам проверены. Первый адаптер уже есть.
- [x] **B02 · Подтверждаемый write, ограниченная локальная интеграция внешнего сервиса.** Prepare, рестарт Loom до approval, выполнение через реальный сервис и повтор approval/status сохраняют один эффект. Это не приёмка любого нового метода.
- [x] **B03, базовый срез · Telegram ↔ Loom.** На выделенном стенде проверены делегированный run, история следующего обращения, ответ в Telegram и восстановление того же run при рестарте клиента/зависимостей. Новый разговорный протокол остаётся ниже.
- [x] **D07/D11 · Динамические лимиты и личная память.** Реализованы и проверены локально. Лимиты применяются на следующей безопасной границе; micro-память перечитывается перед inference.
- [x] **F01/F07/F08/F09 · Discovery, файлы и телеметрия.** Polling 300/3600 принят; временные файлы, range/handle streaming, worker и OTel реализованы. Native сервис → Loom проверяет PDF, аудио/видео и явный refetch внешнего файла. Live transcription этим не закрыта.

## Следующий приоритет

- [ ] **A01/E03 · Авторизация на установленном issuer.** Проверить отзыв роли, expiry, JWKS rotation и purge с warm/cold permission cache. Поддержка proxy/direct panel login уже реализована. Готово: sensitive операции сохраняют online-проверку, обычные запросы соблюдают TTL, purge не допускает повторного использования старого поколения.
- [ ] **A02/D06/D09 · Расширенная live-приёмка модели.** Минимальная связь с OpenAI/accounting проверена. Остаются tools/questions, vision, continuation, native compaction, cache usage и качество выжимок. Готово: usage и settlement согласованы, restart не повторяет эффекты. Платные прогоны требуют согласованного бюджета.
- [ ] **B03/D10 · Разговорный ввод клиента.** Принять RU/EN согласия, отказы, исправления, поздние ответы, порядок доставки и смешанные callbacks. Готово: новый prepare требует нового сообщения; поправка до dispatch блокирует старое действие; неоднозначный текст не разрешает critical write. Старые protocol-mode прогоны этого не доказывают.
- [ ] **C01 · Сквозная диагностика.** Проверить scrape/log/trace delivery, чтение из backend и адресное уведомление. Export приложения, приём коллектора и видимость в панели — отдельные границы.
- [ ] **C02/D02 · Backup, restore и ключи.** Утвердить RPO/RTO и off-host storage. Восстановить БД/ledger/operations с ключами и пройти recovery barrier без повторного write; проверить rotation исторического backup. Временные blobs не становятся архивом.
- [ ] **C03/E01/E02 · Отказы и рабочие пределы.** На выделенном стенде повторить ENOSPC/read-only, outages, SIGTERM/SIGKILL и конкуренцию/OOM; измерить нагрузку, SSE, очередь и shutdown. Не использовать production для разрушительных QA-сценариев.
- [ ] **C04 · Контролируемый pilot и rollback.** Проверить реальные клиентские read/write/reauthorize с малыми квотами. Возврат образа допускается только при совместимой схеме; автоматического down migration нет.

## Последующие изменения

- [ ] **D01 · Refreshable delegation.** Сначала подтвердить поддерживаемый issuer flow. Сейчас expiry требует reauthorize; refresh внутри Loom не реализован.
- [ ] **D03 · Эффект previous-run reuse.** Измерить cache hit/стоимость. Совместимый локальный prefix уже есть; provider previous_response_id и полный transcript не переиспользуются.
- [ ] **D04 · Model token deltas.** Добавлять поверх durable SSE без дублей final result и нарушения billing/cancel.
- [ ] **D05 · Dependency recovery.** Provider hybrid retry уже есть. Определить общий circuit breaker и retry других зависимостей; unknown write не повторять вслепую.
- [ ] **D08 · Lifecycle данных.** Согласовать сроки audit/credentials/recovery/ledger и аудируемое изменение retention существующих ресурсов. Diagnostics API и agent functions уже есть.
- [ ] **E04 · Несколько реплик.** Общие blobs/ключи, disconnect coordination и rolling restart. Текущая поставка не обещает HA.
- [ ] **E01, диагностика теста очереди.** Ранее наблюдался непостоянный недобор recovered rows в TestExhaustedQueueRecoveryPreservesUncertaintyAndLiveWork. Изолированные повторы не доказали причину. При повторе сохранить states/leases/locks; свежий зелёный CI не закрывает неизвестную причину.
- [ ] **E05 · Supply chain инструментов.** Периодически проверять лицензии/native tools и обновлять notices. Отдельного Go lock-файла не требуется.

## По потребности

**F02–F06:** remote cancel, opaque service credentials, WebSocket, private inference/object storage/новые native formats, субагенты и proactive runs. Для них нужен отдельный контракт. Пассивное событие не запускает агента.

Закрывайте задачу по её критериям и проверенному build. Production-свойства не выводятся из local PASS. Отчёты/receipts/dumps хранятся вне репозитория; здесь остаются тесты и инструкции QA.

## History and context

Последовательность чата объединяет сообщения, UI-события и отображаемые факты о run. Большие tool results и raw provider details хранятся отдельно и добавляются в контекст по необходимости. Оригиналы сохраняются согласно retention; выжимка не заменяет их.

Начальный контекст: системная политика, разрешённые инструменты, валидная summary до N, полные необходимые события после N, текущее поручение. Граница N выбирается по токен-бюджету конкретной модели. Резервируется место для output, инструментов и управляющих входов. События вопрос/ответ и tool call/result не разрываются в недопустимую для provider структуру.

Сохраняются цель, актуальные ограничения, принятые решения, открытые вопросы и references на исходные IDs. Approvals, права и бюджет берутся из структурированных записей, никогда из summary. Summary не запускает действий и не расширяет пользовательское поручение.

Summary обновляется, когда свежая история не помещается в заданные ограничения, а не каждый run. Она хранит `through_seq` и `source_hash` входных данных суммаризации. Этот hash служит provenance, а не проверкой целостности при каждом чтении. Публичного редактирования событий нет; удаление чата и lifecycle retention удаляют соответствующие summaries. Если summarization недоступна и прежней выжимки недостаточно, run приостанавливается с `context_unavailable`, а ограничения не обрезаются молча. Слишком большой одиночный input отклоняется; клиент может отдельно загрузить поддерживаемый файл как артефакт и передать его ID, но автоматического преобразования текста в файл нет.

Активный run применяет новые события между шагами. Snapshot сборки контекста имеет верхнюю seq; более поздние события остаются для следующей границы. UI-событие показывает прошлое: перед изменением backend состояние читается заново.

История доступна через literal (default), PostgreSQL fulltext с конфигурацией `simple` и RE2 regex над ограниченным авторизованным диапазоном. Bounded snippets и paged read сохраняют доступ к полным событиям; ответ явно указывает truncation, skipped sequences и продолжение. Опциональный vector API принимает внешние embeddings и выполняет exact cosine ranking через pgvector. `search.semantic_enabled: false` скрывает инструмент и отключает indexing route. Embeddings-сервис и автоматическая индексация не реализованы.
## Credits

Единица — integer microcredit, без floating point. Run сохраняет snapshot тарифа; provider usage и внутреннее списание сохраняются отдельно. Для model шага тариф включает обычный input, cached input, cache-write input и output, с optional long-context band. Cache reads/writes — непересекающиеся части общего input, не дополнительные токены. Сумма input и сумма output отдельно округляются вверх до целого microcredit. Effort сам по себе не заменяет учёт фактических токенов. Формулу задаёт [tariff.go](../../internal/domain/tariff.go).

Перед шагом резервируется верхняя оценка стоимости в рамках max output и provider limits. Если provider не позволяет ограничить оплачиваемый объём достаточно для hard budget, такой режим не включается для жёстко ограниченных аккаунтов до отдельной политики.

После известного usage происходит settlement: reserved освобождается, фактическая стоимость списывается ровно один раз. Неудачная или отменённая генерация тоже может быть платной. При неизвестном usage действует [platform-sponsored policy](../active-compaction.md): подходящая неопределённая попытка учитывается как exposure платформы, а резерв пользователя освобождается. За пределами этой политики резерв остаётся uncertain до привилегированной сверки. Автоматического получения поздней usage сейчас нет; отсутствие usage не означает нулевую стоимость. Manual adjustment требует права, причины и доказательства; история ledger не переписывается.

Резерв создаётся для принятого платного шага; будущие, ещё не принятые шаги не резервируются заранее. При ожидании пользователя резерв неизвестной оплаченной операции сохраняется. Resume и следующий платный шаг требуют доступного бюджета. Summary учитывается как отдельный `summary` step текущего run с его плательщиком, лимитами и tariff snapshot; это не бесплатный фоновый вызов.
